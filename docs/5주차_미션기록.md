## 3. 화면 연결 방식과 이유

### 처음 계획
프론트엔드(Flutter `movielog`) 코드는 건드리지 않고, **백엔드 쪽에서 해결**하는 방향으로 진행하려고 했다.

### 진행하면서 확인한 점
- `movielog`에는 우리 Spring 서버를 호출하는 코드가 없고(영화 데이터는 TMDB만 호출), 앱 화면에 연결하려면 Flutter 쪽에 Client·Service·화면 코드를 추가해야 했다.
- 또 Android 에뮬레이터에서는 `localhost`가 에뮬레이터 자신을 가리켜 `10.0.2.2` 주소와 HTTP 평문 허용 설정이 필요했다.
- 즉 **프론트를 수정하지 않는 조건으로는 Android Studio(에뮬레이터) 연동이 불가능**했다.

### 최종 방식
실습 0에서 사용한 간이 프론트 `mock-frontend/index.html`을 **API 3개를 모두 호출하는 화면으로 직접 수정**하고, `npx serve -l 5173`으로 띄워 **CORS 설정 후 정상 응답을 받는 것**을 확인했다.

- 간이 웹 화면 코드: https://github.com/4824seon-png/11th_UMC_PE_Backend/tree/main/mock-frontend

```
브라우저 (http://localhost:5173, mock-frontend)
   │  fetch GET  (Origin: http://localhost:5173)
   ▼
Spring (http://localhost:8080)  ── WebConfig: allowedOrigins("http://localhost:5173")
   │  응답 헤더 Access-Control-Allow-Origin: http://localhost:5173
   ▼
MySQL (umc_movie)
```

- 화면(5173)과 서버(8080)는 **포트가 달라 cross-origin**이므로, 브라우저 환경에서 CORS가 실제로 적용된다. → 이번 주 주제(CORS)를 직접 확인할 수 있는 구성
- 화면에는 **요청 URL · 상태 코드 · 결과 문구 · 응답 JSON**을 함께 표시해, Postman 결과와 같은 형식으로 비교할 수 있게 했다.
- 참고: Flutter 네이티브 앱(Android)은 브라우저가 아니므로 CORS의 적용을 받지 않는다. CORS는 서버가 요청을 막는 것이 아니라 **브라우저가 스스로 응답 읽기를 제한하는 정책**이기 때문이다.

## 4. CORS 설정 전/후 비교

### 설정 전 (실습 0)
- `http://localhost:5173`에서 버튼 클릭 시 Console 에러

```
Access to fetch at 'http://localhost:8080/members/nickname/noco' from origin 'http://localhost:5173'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
```
- Network 탭: Request Headers에 `Origin: http://localhost:5173`은 있지만, Response Headers에 `Access-Control-Allow-Origin`이 없음
- 📷 Console 에러 캡처 / Network 헤더 캡처

### CORS 설정

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("http://localhost:5173")
                .allowedMethods("GET", "POST", "PATCH", "DELETE")
                .allowedHeaders("*");
    }
}
```

### 설정 후
- 프론트 코드는 수정 없이 서버만 재시작 → Console 에러 없음
- Network 탭 Response Headers에 `Access-Control-Allow-Origin: http://localhost:5173` 추가됨
- 📷 Network 헤더 캡처

| 2 | 닉네임 `새닉네임` → 중복 확인 | 사용 가능한 닉네임 / `{ "available": true }` | 📷 |
| 3 | 이메일 `noco@umc.com` → 중복 확인 | 이미 사용 중인 이메일 / `{ "available": false }` | 📷 |

- 회원이 없는 경우(404)와 회원은 있지만 평점이 없는 경우(200 + `[]`)를 화면에서 다르게 표시했다.

## ⚡ 트러블슈팅

### 이슈 No.1 — 간이 프론트 대신 폴더 목록이 표시됨
**`이슈`**
👉 `http://localhost:5173` 접속 시 버튼 화면 대신 `Index of 4824s/` 폴더 목록이 표시됨

**`문제`**
👉 `npx serve`는 명령을 실행한 현재 폴더를 정적 서버로 띄운다. 터미널이 홈 폴더(`C:\Users\4824s`)에 있는 상태에서 실행해, `index.html`이 없는 홈 폴더 전체가 노출됨 (`.ssh` 등 민감 파일 노출 위험)

**`해결`**
👉 `Ctrl+C`로 즉시 종료 후 `npx serve -l 5173 C:\development\mock-frontend`처럼 폴더 경로를 지정해 재실행

**`참고레퍼런스`**
- https://www.npmjs.com/package/serve

### 이슈 No.2 — 404 응답이 CORS 에러에 가려짐
**`이슈`**
👉 실습 0에서 API가 없어 실제 응답은 404였지만, 콘솔에는 CORS 에러만 표시됨

**`문제`**
👉 `Access-Control-Allow-Origin` 헤더가 없으면 브라우저가 응답(상태 코드·본문)을 JS에 전달하지 않아 실제 원인이 보이지 않음

**`해결`**
👉 CORS 설정 후에는 404 응답도 정상적으로 읽을 수 있었음. CORS 에러가 보이면 서버 로그나 Network 탭의 실제 상태 코드도 함께 확인해야 함

**`참고레퍼런스`**
- https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS

### 이슈 No.3 — Android 에뮬레이터(movielog) 연동 불가
**`이슈`**
👉 Flutter 앱(movielog)을 재실행해도 우리 API가 호출되지 않음

**`문제`**
👉 앱에는 TMDB 호출 코드만 있고 Spring 서버를 호출하는 코드가 없음. 연결하려면 Flutter 쪽에 Client·Service·화면 추가, 에뮬레이터용 주소(`10.0.2.2`)와 HTTP 평문 허용 설정이 필요해 "프론트를 수정하지 않는다"는 조건과 맞지 않음

**`해결`**
👉 프론트 프로젝트는 그대로 두고, 간이 웹 화면(mock-frontend)을 수정해 API 3개를 호출하는 방식으로 변경. 브라우저 환경이라 CORS 설정 전/후 차이도 직접 확인할 수 있었음

**`참고레퍼런스`**
- https://developer.android.com/studio/run/emulator-networking

## 📢 회고
- Postman에서는 문제없던 API가 브라우저에서는 CORS 에러로 막히는 것을 보고, **CORS가 서버가 아닌 브라우저의 정책**이라는 점을 확실히 이해했다.
- CORS 에러는 프론트 코드로는 해결되지 않고, 서버가 응답 헤더로 허락해야 한다는 점을 설정 전/후 Network 헤더 비교로 확인했다.
- 처음에는 Flutter 앱 연동까지 계획했지만, 앱은 브라우저가 아니어서 CORS 대상이 아니고 주소·통신 설정도 달라 이번에는 웹 화면으로 진행했다. 6주차 이후 회원가입·평점 기능을 만들 때 movielog와 직접 연결해 볼 예정이다.
